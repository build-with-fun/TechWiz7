# SonicSentinel AI — current working state

Updated 2026-09-25 after the SRS overhaul. This file records tested behavior in the
current working tree. The original baseline remains in `PROJECT_AUDIT.md`; the details
of the changes and limitations are in `HUMANIZATION_REPORT.md`.

The Flask app loads two independent saved models: the Python classifier in
`python_models/best/` and the separately trained Google Teachable Machine audio export
in `gtm_model/`. The GTM TensorFlow.js files, converted Keras file, and frontend config
are present. A real HTTP WAV upload returned 201 and persisted its event and audio;
the regression test checks that both models wrote confidence distributions. A fresh
database seed created six demo accounts and registered both matching model versions.

The GTM server path was evaluated on all 450 held-out test clips, 45 per class. It scored
**0.2778 accuracy, 0.2755 macro F1 and 0.3200 critical-class recall**. The Python
model's recorded full-test score is **0.6978 accuracy, 0.6968 macro F1 and 0.8000
critical-class recall**. Neither model meets the SRS target. Browser/server GTM feature
parity has not been measured; `frontend_verified` is false. The app is a review
prototype and should not be deployed as an unattended safety detector.

The local dataset and generated GTM import ZIPs are ignored by Git. A clean clone
needs the authorized corpus separately to reproduce training or dataset verification.
The full browser role/device journey, all supported audio formats, deployment, load,
and latency targets remain unverified. See `TEST_PLAN.md` for the case-by-case status.
The base dependency list passes a local no-download pip dry run, but `pip check` reports
two optional packages already present in this `.venv` with inconsistent dependency
metadata (`tensorflow-cpu` and `tensorflowjs`); a clean-environment install is pending.
