{# ========================================================================== templates/base.html — the application shell. Context keys this template relies on. They are sara's context-processor contract, and the file fails loudly if they go missing, which is deliberate: config (ConfigStore) nav severity_scale severity_levels class_names critical_classes role_labels model_labels quality_verdicts consistency_statuses alert_statuses review_decisions review_conditions app_name app_version request_id current_user (Flask-Login, with .can(capability) and .role) Two rules worth stating out loud because they cause real bugs: 1. **Access is gated on `current_user.can('capability')`, never on a role string.** Moving a capability between roles in src/auth.py must not need a template edit. There is one helper (`_can`) and everything uses it. 2. **Nothing inline executes.** The app is served with `script-src 'self'; style-src 'self'` (config/auth.json), so there are no inline {% block scripts %}{% endblock %}
