{# ---------------------------------------------------------------- console #}

The console

What happened, and what needs a decision

The console puts the latest detection, the alert and review queues and the evidence in one place. It works the same on a phone at the door as on the control-room screen.

  • {{ ui.icon('cpu', 18) }}

    Both opinions, side by side

    Python and Teachable Machine each give a class, a confidence and a top three, with the gap between them.

  • {{ ui.icon('clipboard', 18) }}

    Queues that say why

    Every item held back for review lists its reason: disagreement, low confidence, poor audio or an overlap.

  • {{ ui.icon('spectrogram', 18) }}

    Evidence on every event

    Waveform, spectrogram and playback sit next to the verdict, so a reviewer can hear what the models heard.

  • {{ ui.icon('mic', 18) }}

    Live, with consent first

    Nothing is captured until the consent box is ticked, and the microphone state is always on screen.

  • {{ ui.icon('bell', 18) }}

    Alerts that wait for proof

    Critical classes need matching windows in a row before an alert is raised, then go to an operator.

  • {{ ui.icon('download', 18) }}

    Reports and a full audit trail

    Download an event report, export CSV or Excel, and see who uploaded, reviewed or changed what.

{# ----------------------------------------------------------- how it works #}

How it works

From a sound to a decision, in four checks

No step trusts the one before it blindly. Bad audio is stopped early, and a prediction is only acted on when two independent models and the rules agree.

Try it with a sample clip →
  1. {{ ui.icon('upload', 18) }}

    Capture

    Upload a file, or monitor a microphone in two-second windows once consent is ticked.

    • WAV
    • MP3
    • FLAC
    • OGG
    • M4A
    • Live mic
  2. {{ ui.icon('waves', 18) }}

    Check the audio

    Silence, clipping and background noise are measured first. Unusable audio is refused with the reason.

    • Good
    • Acceptable
    • Poor → review
    • Unusable → refused
  3. {{ ui.icon('cpu', 18) }}

    Classify twice

    Our Python model and a Teachable Machine model each score all ten classes. Neither sees the other's answer.

    • AST embeddings
    • Teachable Machine audio
    • Top three each
  4. {{ ui.icon('shield', 18) }}

    Decide

    Agreement, the confidence gap and audio quality set the verdict. Critical sounds raise alerts; uncertain ones go to a reviewer.

    • Strong match
    • Disagreement
    • Uncertain
    • Alert
